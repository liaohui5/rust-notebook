## 介绍

在软件运行期间, 收集日志是用来观测软件是否正常运行的重要信息来源,
这就需要在编码时就把日志当作可观测性接口来设计, 而不是等运行出问题后临时加 `println`
在 Rust 生态中, 有很多日志库可以使用, 但是最重要的是 [log](https://crates.io/crates/log)
它与 `serde` 类似, 只提供了一些 trait, 并没有具体的实现, 要使用具体实现, 需要安装其他日志库, 如:

- [env_logger](https://crates.io/crates/env_logger) 最简单/易用的日志库
- [tracing](https://crates.io/crates/tracing) 异步应用专用日志收集库,由 Tokio 团队维护

## log 主要API

log 主要提供了一些宏, 用法类似 [format!](<>)

| 宏     | 级别  | 典型用途         |
| ------ | ----- | ---------------- |
| trace! | TRACE | 最详细的追踪信息 |
| debug! | DEBUG | 调试信息         |
| info!  | INFO  | 常规运行信息     |
| warn!  | WARN  | 警告             |
| error! | ERROR | 错误             |

### 自定义日志格式

格式化日志可用元素

| 方法                   | 说明             |
| ---------------------- | ---------------- |
| buf.timestamp()        | 默认格式的时间戳 |
| buf.timestamp_millis() | 毫秒级时间戳     |
| buf.timestamp_nanos()  | 纳秒级时间戳     |
| record.level()         | 日志级别         |
| record.target()        | 日志来源模块路径 |
| record.args()          | 日志消息         |

```rust
use env_logger;
use log;
use std::io::Write; // 注意导入 trait

fn main() {
    // 使用默认配置初始化日志(默认是 error 级别的日志)
    // env_logger::init();

    // 自定义配置初始化日志
    env_logger::Builder::new()
        .format(|buf, record| {
            // 1.自定义日志的格式化函数
            writeln!(
                buf,
                "[{}][{}] - {}",
                buf.timestamp(),
                record.level(),
                record.args()
            )
        })
        // 2.日志是否输出颜色信息(WriteStyle::Always/Never/Auto)
        // Always: 必须输出颜色信息
        // Auto  : 由 env_logger 自己决定是否输出
        // Never : 禁止输出颜色信息
        .write_style(env_logger::WriteStyle::Always)
        // 3.日志输出过滤级别
        .filter(None, log::LevelFilter::Trace)
        .init();

    log::trace!("这是一条 trace 日志");
    log::debug!("这是一条 debug 日志");
    log::info!("这是一条 info  日志");
    log::warn!("这是一条 warn  日志");
    log::error!("这是一条 error 日志");
}
```

### 实现日志双写

所谓的日志双写就是: `将日志同时写入出到 stdout 和文件`

```rust {6-32,34-58,64-68}
use env_logger;
use log;
use std::io::{self, Write};
use std::{fs, path};

// 关键步骤2: 使用自定义的 writer 来控制日志应该写入到哪里去
/// 自定义 Writer: 同时写入控制台和文件
struct MutilWriter {
    console: Box<dyn Write + Send>, // 日志输出到 stdout
    log_file: Option<fs::File>,     // 日志输出到文件
}

impl MutilWriter {
    fn new(log_save_path: impl AsRef<path::Path>) -> io::Result<Self> {
        let log_path_buf = log_save_path.as_ref().to_path_buf();
        let file = Self::open_file(&log_path_buf)?;

        Ok(Self {
            console: Box::new(io::stdout()),
            log_file: Some(file),
        })
    }

    /// 根据日期打开(或创建)日志文件
    fn open_file(log_file_path: &path::Path) -> io::Result<fs::File> {
        // 如果文件不存在则创建, 准在则追加文件内容
        fs::OpenOptions::new()
            .create(true)
            .append(true)
            .open(log_file_path)
    }
}

// 关键步骤3: 自定义的日志写入器必须实现 std::io::Write 这个 trait
impl Write for MutilWriter {
    fn write(&mut self, buf: &[u8]) -> io::Result<usize> {
        // 写入 stdout 处理
        self.console.write_all(buf)?;

        // 写入文件处理
        if let Some(file) = &mut self.log_file {
            file.write_all(buf)?;
        }
        Ok(buf.len())
    }

    fn flush(&mut self) -> io::Result<()> {
        // stdout 处理
        self.console.flush()?;

        // 文件处理
        if let Some(file) = &mut self.log_file {
            file.flush()?;
        }

        Ok(())
    }
}

/// 初始化日志系统
pub fn init_logging() -> Result<(), Box<dyn std::error::Error>> {
    let writer = MutilWriter::new("app.log")?;

    let log_level = env_logger::Env::default().default_filter_or("info");
    env_logger::Builder::from_env(log_level)
        // 关键步骤1: 调用 target 设置日志输出目标(自定义日志写入器)
        .target(env_logger::Target::Pipe(Box::new(writer)))
        .init();

    Ok(())
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    init_logging()?;

    log::trace!("这是一条 trace 日志");
    log::debug!("这是一条 debug 日志");
    log::info!("这是一条 info  日志");
    log::warn!("这是一条 warn  日志");
    log::error!("这是一条 error 日志");

    Ok(())
}
```

### 实现日志时间分片

所谓的日志时间分片就是: `将不同时间的日志写入到不同时间命名的文件中`,
比如: 2020-10-10 这一天的日志就写入到 `2020-10-10.log` 这个文件中, 上面已经实现了日志双写,
那么只要在写入文件的时候, 动态生成文件名, 然后判断是否需要轮转即可实现: 日志写入文件时
`写入到按照日期分类的的文件中`

```rust {23-25,44-54,58-68}
// 由于需要处理日期,所以注意需要安装日期信息处理依赖: chrono = "0.4"
use chrono::Local;
use env_logger;
use log;
use std::io::{self, Write};
use std::{fs, path};

/// 自定义 Writer: 同时写入控制台和按日期轮转的文件
struct DailyMutilWriter {
    console: Box<dyn Write + Send>, // 输出日志到 stdout
    log_dir: path::PathBuf,         // 日志文件保存目录
    log_file: Option<fs::File>,     // 日志文件句柄
    current_date: String,           // 当前日志
}

impl DailyMutilWriter {
    fn new(logs_save_path: impl AsRef<path::Path>) -> io::Result<Self> {
        let log_save_dir = logs_save_path.as_ref().to_path_buf();

        // 确保目录存在
        fs::create_dir_all(&log_save_dir)?;

        // 关键实现1: 根据日动态生成文件名
        let today = Local::now().format("%Y-%m-%d").to_string();
        let file = Self::open_file(&log_save_dir, &today)?;

        Ok(Self {
            console: Box::new(io::stdout()),
            log_dir: log_save_dir,
            log_file: Some(file),
            current_date: today,
        })
    }

    /// 根据日期动态打开(或创建)日志文件
    fn open_file(log_save_path: &path::Path, date: &str) -> io::Result<fs::File> {
        let log_file_path = log_save_path.join(format!("{}.log", date));
        fs::OpenOptions::new()
            .create(true)
            .append(true)
            .open(log_file_path)
    }

    /// 检查日期是否变化, 若有变化则切换文件
    fn check_rotation(&mut self) -> io::Result<()> {
        // 关键实现2: 每次检查, 当前日期是否与保存的日志一致, 不一致说明需要轮换
        let today = Local::now().format("%Y-%m-%d").to_string();
        if today != self.current_date {
            let log_file = Self::open_file(&self.log_dir, &today)?;
            self.log_file = Some(log_file);
            self.current_date = today;
        }
        Ok(())
    }
}

impl Write for DailyMutilWriter {
    fn write(&mut self, buf: &[u8]) -> io::Result<usize> {
        // 关键实现3: 每次写入前检查日志文件是否需要轮转
        self.check_rotation()?;

        // 同时写入控制台和文件
        self.console.write_all(buf)?;
        if let Some(file) = &mut self.log_file {
            file.write_all(buf)?;
        }
        Ok(buf.len())
    }

    fn flush(&mut self) -> io::Result<()> {
        self.console.flush()?;
        if let Some(file) = &mut self.log_file {
            file.flush()?;
        }
        Ok(())
    }
}

/// 初始化日志系统
pub fn init_logging() -> Result<(), Box<dyn std::error::Error>> {
    let writer = DailyMutilWriter::new("logs")?;

    let log_level = env_logger::Env::default().default_filter_or("info");
    env_logger::Builder::from_env(log_level)
        .target(env_logger::Target::Pipe(Box::new(writer)))
        .init();

    Ok(())
}

fn main() -> Result<(), Box<dyn std::error::Error>> {
    init_logging()?;

    log::trace!("这是一条 trace 日志");
    log::debug!("这是一条 debug 日志");
    log::info!("这是一条 info  日志");
    log::warn!("这是一条 warn  日志");
    log::error!("这是一条 error 日志");

    Ok(())
}
```

### 实现日志双写与分片

- 注意需要安装 `tracing-appender` 依赖: `cargo add tracing-appender`

::: code-group

```rust [异步日志文件写入不阻塞主线程]
use tracing::{debug, error, info, instrument, trace, warn};
use tracing_appender::non_blocking::WorkerGuard;
use tracing_subscriber::layer::SubscriberExt;
use tracing_subscriber::util::SubscriberInitExt;
use tracing_subscriber::{self, EnvFilter, fmt};

fn init_logger() -> WorkerGuard {
    // 0.确保目录存在
    std::fs::create_dir_all("logs").expect("failed to create logs dir");

    // 1.使用 export RUST_LOG=debug 这样的环境变量来控制日志过滤级别
    let env_filter_layer = tracing_subscriber::EnvFilter::try_from_default_env()
        .unwrap_or_else(|_| EnvFilter::new("info"));

    // 2.创建写入文件的 layer
    // 2.1)创建按天滚动的文件 appender, 生成的文件路径类似于: logs/app.log.2026-09-24
    // 2.2)使用 non_blocking 包装文件写入器, 避免阻塞主线程
    // 2.3)注意写入文件中的是 json 格式, 方便后续编程处理
    let file_appender = tracing_appender::rolling::daily("logs", "app.log");
    let (async_file_writer, guard) = tracing_appender::non_blocking(file_appender);
    let file_writer_layer = fmt::layer()
        .json()
        .with_writer(async_file_writer)
        .with_ansi(false)
        .with_target(true)
        .with_file(true)
        .with_thread_ids(true);

    // 3.创建写入 stdout 的 layer
    // 3.1) 注意设置输出到 stdout 的信息字段(并不是 JSON 格式的)
    let console_writer_layer = fmt::layer()
        .with_writer(std::io::stdout)
        .with_target(true)
        .with_thread_names(true)
        .with_file(true)
        .with_ansi(true);

    // 4.初始化
    // 4.1) 注意处理错误
    tracing_subscriber::registry()
        .with(env_filter_layer)
        .with(file_writer_layer)
        .with(console_writer_layer)
        .try_init()
        .expect("failed to init logger");

    // 5.注意要返回这个 guard, 否则这个函数执行完
    // guard 就被释放了, 那么就不会将内容写入到文件中了
    // 所以必须要返回它, 让他的生命周期延长至 main 函数结束
    // 然后再释放掉它
    guard
}

fn main() {
    let _guard = init_logger();

    // 输出日志
    trace!("trace log message");
    debug!("debug log message");
    info!("info log message");
    warn!("warn log message");
    error!("error log message");

    // 监控其他函数的日志
    let a = 11;
    let b = 22;
    let res = sum(a, b);
    info!("sum({a}, {b}) = {res}");
}

#[instrument]
fn sum(a: i32, b: i32) -> i32 {
    info!("a={a}, b={b}");
    a + b
}
```

use tracing_subscriber::util::SubscriberInitExt;
use tracing_subscriber::{self, EnvFilter, fmt};

fn init_logger() {

    std::fs::create_dir_all("logs").expect("failed to create logs dir");

    // 1.使用 export RUST_LOG=debug 这样的环境变量来控制日志过滤级别

    // 2.创建写入文件的 layer
    // 2.1)创建按天滚动的文件 appender, 生成的文件路径类似于: logs/app.log.2026-09-24
    // 2.2)使用 non_blocking 包装文件写入器, 避免阻塞主线程
    // 2.3)注意写入文件中的是 json 格式, 方便后续编程处理
    let file_appender = tracing_appender::rolling::daily("logs", "app.log");
    // let (async_file_writer, guard) = tracing_appender::non_blocking(file_appender);
    let file_writer_layer = fmt::layer()
        .json()
        .with_writer(file_appender) // 直接传入 file_appender, 不需要异步写入 guard 了
        .with_ansi(false)
        .with_target(true)
        .with_file(true)
        .with_thread_ids(true);

    // 3.创建写入 stdout 的 layer
    // 3.1) 注意设置输出到 stdout 的信息字段(并不是 JSON 格式的)
    let console_writer_layer = fmt::layer()
        .with_writer(std::io::stdout)
        .with_target(true)
        .with_thread_names(true)
        .with_file(true)
        .with_ansi(true);

    // 4.初始化
    // 4.1) 注意处理错误
    tracing_subscriber::registry()
        .with(env_filter_layer)
        .with(file_writer_layer)
        .with(console_writer_layer)
        .try_init()
        .expect("failed to init logger");
}

fn main() {
    init_logger();

    // 输出日志
    trace!("trace log message");
    debug!("debug log message");
    info!("info log message");
    warn!("warn log message");
    error!("error log message");

    // 监控其他函数的日志
    let a = 11;
    let b = 22;
    let res = sum(a, b);
    info!("sum({a}, {b}) = {res}");
}

#[instrument]
fn sum(a: i32, b: i32) -> i32 {
    info!("a={a}, b={b}");
    a + b
}

::: info 提示

以 Rust 的性能来说, 同步的方案就足够大部分应用了
但是一些应用可能需要更极致的性能, 比如一些 web 服务端项目,
一些接口可能在一分钟之内要调用成千上万次, 那么就需要异步的写入文件的方案了,
只是要注意: `guard 的释放时机, 过早释放会导致日志无法正确写入文件`
